### 11/10 a 19/10 — JavaScript e estrutura semântica

Nesta etapa o site ganhou JavaScript e passou a seguir a estrutura que o professor pediu:

```
header  →  nav  →  main  →  footer
                    ├── section / article   (conteúdo, à esquerda)
                    └── aside               (informações extras, à direita)
```

- O `nav` saiu de dentro do `header` e virou uma faixa própria.
- O `aside` acompanha a rolagem no computador (`position: sticky`) e vai para baixo do conteúdo no celular.
- O `acessibilidade.js` guarda as opções do painel no `localStorage`. Ele é carregado logo depois do painel, sem `defer`, para o tema escuro não "piscar" claro ao trocar de página.

## Decisões técnicas

- **Um CSS compartilhado e um por página.** O `style.css` tem as cores, o cabeçalho, o menu, o rodapé, os formulários e a acessibilidade. Cada integrante mexe só no próprio `pagN.css`, o que diminui os conflitos no Git.
- **Cores só por variáveis** (`var(--cor-texto)`, `var(--cor-fundo-cartao)`...). É isso que faz o tema escuro e o alto contraste funcionarem em todas as páginas sem reescrever regra por regra.
- **Caminhos relativos** (`../css/style.css`, `pag1.html`). Caminhos começando com `/` funcionavam no Live Server, mas quebravam no GitHub Pages e abrindo o arquivo direto. Em 22/10 eles foram trocados nas 14 páginas e, em 04/11, também na página 11.
- **O JavaScript só acrescenta.** Curtir, salvar, reações e o painel de acessibilidade funcionam só com HTML e CSS (checkbox/radio + `:has()`). O JavaScript entra para salvar escolhas, publicar posts, filtrar listas e mostrar avisos.
- **Texto digitado pelo usuário entra com `textContent`**, nunca com `innerHTML`, para não virar código na página.
- **Um `index.html` na raiz** leva para `paginas/Inicio.html`, para o link do GitHub Pages abrir direto no site.

## Principais aprendizados

- Organização de pastas faz diferença quando o projeto cresce e muita gente mexe junto.
- Tags semânticas (`header`, `nav`, `main`, `section`, `article`, `aside`, `footer`) deixam o código mais fácil de entender e ajudam os leitores de tela. Uma `section` precisa de um título; quando é só para agrupar, o certo é `div`.
- O HTML5 já valida formulários sozinho com `required`, `type` e `pattern`. O evento `submit` só acontece quando o formulário passa nessa validação.
- Variáveis de CSS permitem mudar o tema do site inteiro mudando poucos valores.
- O `localStorage` guarda dados no navegador entre uma página e outra, mas só no computador de quem está usando.
- Um arquivo `.js` só funciona se a página tiver a linha `<script src="...">` chamando ele.
- Um erro de sintaxe (uma chave `}` faltando, por exemplo) faz o arquivo JavaScript inteiro parar de funcionar.
- Combinar quem mexe em qual arquivo evita conflitos no Git.

## Principais dificuldades

- **Conflitos de merge no Git.** A página de Mensagens chegou a ficar com as marcas `<<<<<<<`, `=======` e `>>>>>>>` aparecendo na tela.
- **Visual diferente entre páginas** enquanto cada uma tinha o próprio CSS completo, com cores próprias e até cabeçalho de outro projeto.
- **Imagens e GIFs pesados.** Uma imagem de 2,5 MB e um GIF de 6,2 MB precisaram ser reduzidos.
- **Arquivos de versões diferentes misturados.** Um `pag1.html` antigo com um JavaScript novo fazia os posts pararem de funcionar. A solução foi trocar os arquivos juntos e recarregar com Ctrl + F5 por causa do cache.
- **Git sem identidade configurada** num computador novo (`unable to auto-detect email address`). A solução foi `git config user.name` e `git config user.email`.
- **`git pull` bloqueado por alterações locais.** A solução foi guardar as alterações com `git stash`, fazer o `pull` e depois conferir.
- **Arquivos enviados no lugar errado**, como a página de Projetos salva dentro da pasta `css/` e uma cópia `pag.4.html` que começava com ```` ```html ````.

## Limitações conhecidas

- Posts, curtidas, reações e escolhas do painel ficam salvos só no navegador de quem usa (`localStorage`). Para outras pessoas verem, seria preciso um back-end com banco de dados.
- Os formulários mostram uma mensagem de confirmação, mas não enviam os dados para nenhum servidor.
